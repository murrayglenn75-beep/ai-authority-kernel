# AAK v1.5.0-rc1 critical hardening report

## Why this release exists

A critical review of v1.4 found that its architecture was stronger than its
deployment evidence and exposed three locally fixable cross-service weaknesses.
This release fixes those weaknesses rather than increasing simulation counts
without changing the trust boundary.

## Findings and fixes

### Broker bypass and replay

Previously, the broker verified the signed grant but did not prove that the
authorization audit had committed, and broker verification was not itself
single-use. A compromised resource could bypass resource-side consumption and
replay a still-valid grant.

The broker now requires the exact `action_authorized` event and its signed audit
receipt. It verifies the receipt, event hash, action hash and grant bindings,
then atomically consumes the envelope in a credential-domain SQLite ledger
before calling the provider. Concurrent and post-restart replay tests permit
exactly one provider call.

### Caller-controlled time

Remote resource and broker requests previously carried `now`. A compromised
caller could backdate execution. Time is no longer present in either wire
schema. Each service obtains time from an injected process-owned clock.

### Valid-prefix audit rollback

A hash chain alone cannot detect restoration of an older internally valid
snapshot. The audit anchor now exports a signed head checkpoint and can require
that checkpoint at startup. If the database no longer contains that exact
signed head, startup fails with `audit_rollback_detected`. The checkpoint must
be retained off-host for this guarantee to matter.

### Interaction-point overload

The mutual-TLS host now bounds concurrent workers, applies per-connection
deadlines, rejects transfer encoding and duplicate content-length framing,
bounds headers, restricts health access to allowed SPIFFE identities and emits
structured accepted/denied/unavailable events.

## Evidence collected

- 192 deterministic tests passed with resource warnings promoted to errors.
- Six 100,000-case attack campaigns completed with zero unauthorized effects,
  zero unauthorized acceptances and zero crashes.
- 310,000 resilience operations completed with zero unauthorized or duplicate
  effects and zero crashes.
- 1,653 HTTP operations preserved audit integrity and produced zero unauthorized
  or duplicate effects.
- Mutual TLS accepted the trusted identity and rejected two unauthorized cases.

## Still not proved

Docker was unavailable. Live service containers, enforced network policy,
OPA/OIDC/PostgreSQL interoperability, KMS/HSM signing, certificate rotation
under traffic, database failover, host compromise resistance and independent
penetration testing remain required. These are not replaced by local tests.
