# AAK v1.0.0-rc3 defensive bug audit

Date: 2026-09-15

## Confirmed defects fixed

| Defect | Risk | Fix |
|---|---|---|
| Global policy revision namespace | Cross-policy denial of service | Namespace by issuer, audience and policy hash |
| Global replay identifiers | Cross-domain identifier collision | Namespace replay keys by complete trust domain |
| Non-Boolean signed policy result accepted as truthy | Faulty PDP could authorize malformed result | Require exact Boolean type |
| Weak signed field bounds | Storage/memory abuse and malformed state | Validate revision, time and identifier lengths |
| Optional workload channel binding | Assertion reuse outside original request | Require verified request-body binding |
| Assurance consumed before dispatch validation | Captured proof could be burned with bad dispatch | Perform all stateless checks before one-time assurance |
| Effect reservation read-then-insert | Multi-process race could raise | `BEGIN IMMEDIATE` atomic reservation |
| Unconditional rollback after failed begin | Secondary exception could mask outage | Roll back only when a transaction exists |
| Malformed Python API objects could raise | Availability failure at internal boundary | Explicit type checks and fail-closed hashing |
| Resolver/evaluator exceptions escaped | Authority-service crash | Convert dependency exceptions to denial |
| State/audit/assurance outage exceptions escaped | Request handler crash | Return explicit unavailable denial before effects |

## Verification

- 113/113 deterministic tests passed.
- 100,000 assurance mutations: zero unauthorized acceptances and zero crashes.
- 100,000 compound attacks: zero unauthorized effects and zero crashes.
- Regression tests cover domain isolation, signed type confusion, proof-burning,
  closed databases, malformed objects, dependency exceptions, channel mismatch,
  restart persistence and multi-process-safe effect reservation.

## Remaining limitations

No local test proves real OPA/SPIRE/KMS/PostgreSQL/provider behavior. Those remain
deployment acceptance tests. Passing this audit is not a claim of formal proof,
independent penetration testing or production certification.
