# AAK v0.8.2 production-like validation

## Environment

The test used real localhost TCP/HTTP traffic, a threaded service adapter,
canonical JSON decoding, server-owned proof verification, Ed25519 signatures,
a file-backed SQLite state store and concurrent clients. Effects remained local
and simulated; no external service was targeted.

## Results

- HTTP requests: 1,653
- Authorized local effects: 502
- Unauthorized or duplicate effects: 0
- Unhandled crashes: 0
- Median latency for the 500-request valid concurrent run: 149.78 ms
- 95th percentile latency: 219.03 ms
- Full audit integrity after the campaign: passed
- Sectional tests: 86/86 passed

The network campaign included 500 valid concurrent transactions, 100 captured
request replays, 50 fresh transport proofs racing one business transaction,
1,000 malformed or oversized messages, an injected audit outage and a valid
follow-up request after quarantine.

## Defects found and corrected

1. The test HTTP adapter inherited a connection backlog too small for the
   intended concurrency. It now has a bounded 128-connection queue. A real
   deployment must use a production gateway with explicit worker and queue
   limits rather than this reference server.
2. Authority claims converted exact integer limits to JSON floats while the
   strict network parser rejects floats. Exact integral values are now retained
   as integers throughout the signed wire protocol.
3. Full audit history was revalidated before every effect, producing quadratic
   latency: 100 actions took 2.15s, 500 took 48.03s and 1,000 took 187.20s.
   Execution now verifies signed incremental head continuity. Full history is
   verified at initialization and through the independent monitor API. The
   corrected 1,000-action run completed in 2.49s and passed full verification.
4. A caller could supply the transport verifier object to the secure execution
   method. The downstream now owns a one-time-bound verifier and rejects object
   substitution.
5. Tenant validation depended on the authority layer. The downstream now
   independently resolves the expected tenant and rejects cross-tenant claims,
   even when a compromised quorum signs them.

## Defensive overlap

The accompanying `SECTIONAL_OVERLAP_REPORT.md` maps first-line and fallback
controls. Tenant, quorum, version, sender identity, replay, effect, state and
audit attacks now have independent enforcement overlap. Remaining single-domain
dependencies are the production HTTP adapter, administrative policy deployment,
external immutable audit storage and network admission infrastructure.
