# AAK v0.8.1 overload and failure-logic report

## Findings corrected

1. Replay-cache expiry copied the complete cache on every verified request.
   This caused quadratic CPU growth. It now uses an ordered expiry queue and
   constant-amortized cleanup.
2. The compound guard bounded identities but did not bound events belonging to
   one authenticated identity. Events are now capped per source and excess
   traffic trips the circuit breaker.
3. Guard cleanup scanned all identities for every incoming signal. It now
   prunes the active identity and performs global cleanup at a bounded cadence.
4. Trusted identity length, boundary names and server timestamps were not
   fully bounded. They now have strict validation and fixed boundary names.
5. An allowed guard check discarded the accumulated score in its result. It
   now returns the current score and participating boundaries.

The 10,000-request transaction race allowed one reservation and rejected 9,999
duplicates. The replay cache admitted its configured 10,000 entries, rejected
the next 40,000 safely, and stayed at its bound.

## Remaining production limits

This local run does not establish maximum production throughput or resistance
to network, kernel, database, HSM/KMS, container-runtime or cloud-control-plane
failure. Production load tests must run against the deployed topology with
latency objectives, resource quotas, multiple hosts, dependency fault injection
and recovery verification. Durable nonce and transaction retention must be
sized from the real settlement and replay window.
