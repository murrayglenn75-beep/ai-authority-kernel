# AAK v1.0.0-rc1 external assurance report

Date: 2026-09-15

## Implemented gap closures

- Signed external policy decisions with exact proposal, policy hash, audience,
  validity window, unique decision ID and monotonic revision binding.
- Independently signed workload assertions binding identity, trust domain,
  audience, certificate fingerprint and validity window.
- Optional verifiers are mandatory at the downstream boundary when configured.
- Explicit versioned assurance schemas reject unknown versions.
- Provider-neutral protocols allow OPA/Cedar and SPIFFE/cloud adapters without
  embedding those products into the authorization kernel.
- Durable effect state machine: prepared, submitted, succeeded, failed and
  ambiguous, with guarded transitions and request-hash idempotency.
- Downstream execution now journals provider submission before invoking the
  effect. Exceptions become ambiguous and quarantine the workload; they are not
  treated as safe-to-retry failures.
- A future-proofing contract defines stable invariants, replaceable adapters,
  migration order and adapter qualification tests.

## Honest boundary

This release closes software architecture and local verification gaps. It does
not create the operational history of OPA, SPIRE, Zanzibar-style platforms or
payment networks. Real deployment evidence still requires separately
administered services, HSM/KMS keys, replicated storage, network isolation,
provider sandbox reconciliation, failover exercises, monitoring and an
independent security assessment.
