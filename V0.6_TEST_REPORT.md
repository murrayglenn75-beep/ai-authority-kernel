# AAK v0.6 security validation

Date: 2026-09-14

## Results

- 73 deterministic unit/security tests passed.
- 20,008 legacy capability attacks caused zero unauthorized effects.
- 5,000 random wire messages failed closed or were accepted only when exactly
  canonical and schema-valid.
- 2,000 mutated sender proofs produced zero successful verifications.
- Concurrent idempotency and audit-ordering scenarios passed 100 repeated runs.
- Dependency consistency, clean wheel import and ZIP integrity passed.

## Defects found during implementation

1. Receipt verification code was displaced while the policy gate was added,
   causing valid verification to return no result. Tests caught and fixed it.
2. The v0.5 audit client relied on the anchor service to report its own
   integrity. v0.6 retrieves the signed records and verifies signatures,
   hashes, sequence and continuity locally.
3. Nonces prevented capability replay but did not prevent a second capability
   for the same business transaction. Atomic tenant-scoped idempotency now
   closes that route.
4. Workload identity was previously only a string comparison. v0.6 adds
   application-layer proof-of-possession; real deployment must bind its key to
   mTLS/SPIFFE or DPoP identity.
5. Effect limits permitted floating-point units. Consequential effects in the
   federated path must now be integer minor units.

## Honest assurance boundary

This is a tested reference implementation, not a certification of a deployed
environment. PostgreSQL/serializable state, HSM/KMS keys, workload attestation,
service isolation, WORM audit storage, rate limiting, signed builds and an
independent penetration test are still required for production assurance.
