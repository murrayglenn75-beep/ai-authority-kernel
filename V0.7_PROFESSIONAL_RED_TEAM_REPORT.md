# AAK v0.7 defensive red-team report

## Result

- Campaign: deterministic, local, authorized defensive simulation
- Attempts: 1,000,000
- Unauthorized acceptances: 0
- Unhandled crashes: 0
- Regression suite after hardening: 79/79 passed
- Seed: 20260916

The campaign mutated authority claims, tenant identity, policy and system
versions, audiences, proposal hashes, declared effects, sender subjects,
routes, methods, body hashes, JSON encodings, duplicate keys, payload sizes and
random wire bytes. The success condition was any unauthorized dispatch or
sender-proof verification.

## Weaknesses found during professional review and fixed

1. Authorities could sign a caller-selected tenant identifier. Authorities now
   resolve and validate the tenant independently from the proposal identity.
2. Sender proof bound the signing key but not the asserted workload subject.
   The signed subject is now verified at both transport and execution layers.
3. Replay-proof memory was unbounded. The cache is now time-pruned, bounded and
   fails closed at capacity.
4. Gateway and downstream time comparisons could receive malformed types.
   Time fields now require non-boolean integers and malformed claims fail closed.
5. Signed policy releases lacked freshness enforcement. Stale, future and
   malformed releases are now rejected before quorum activation.
6. Strict execution budgets used SQLite REAL storage. The enforcement path now
   uses exact signed 64-bit INTEGER accounting and rejects floats, negatives and
   out-of-range values.

## What this result proves

For the tested code paths and attacker models, the campaign did not find a way
to convert mutated or malformed inputs into an authorized dispatch or verified
sender request. The regression suite verifies replay, quorum, idempotency,
resource-version, audit-integrity, identity and budget controls.

## What it does not prove

This is not a claim of bulletproof security or a substitute for an independent
penetration test. A single-process simulation cannot validate real HSM/KMS key
custody, mTLS or SPIFFE identity, cloud IAM, network segmentation, downstream
provider idempotency, CI/CD integrity, multi-host audit durability or resistance
after enough independent trust domains are simultaneously compromised.

Production acceptance therefore requires separate authority, gateway, executor
and audit trust domains; non-exportable keys; sender-constrained identity;
downstream capability verification; externally enforced limits; immutable audit
replication; crash reconciliation; operational monitoring; and an independent
security assessment.

## Compound attack addendum

A second campaign executed 100,000 compound attempts that altered multiple
boundaries in the same request. Scenarios combined compromised-model proposals,
tenant substitution, one compromised authority, duplicate and foreign quorum
signatures, gateway-key misuse, captured capabilities, proposal/body
substitution, workload impersonation, route/method/audience rebinding, and
temporal/key substitution.

- Compound attempts: 100,000
- Unauthorized effects: 0
- Unhandled crashes: 0
- Rejected at authority/quorum boundary: 40,000
- Rejected at transport proof boundary: 60,000

A separate simultaneous race sent 50 individually valid, freshly signed
authority and transport requests for one business transaction. Exactly one
effect executed; the other 49 were rejected as duplicate transactions.
