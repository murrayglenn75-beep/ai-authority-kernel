# AAK v1.0.0-rc2 gap-closure report

Date: 2026-09-15

## Gap closures derived from mature systems

| Source pattern | AAK implementation | Local evidence |
|---|---|---|
| OPA-style independent PDP | Signed external decisions bound to exact input, policy, revision, audience and time | Tamper, denial, expiry, replay and outage paths fail closed |
| SPIFFE-style workload identity | Signed trust-domain assertion bound to certificate and verified request body | Foreign identity, altered channel, expiry and replay denied |
| Zanzibar-style consistency | Durable monotonic policy revision floor and atomic replay records | Rollback and replay remain denied after verifier/database restart |
| Payment-network semantics | Durable effect state machine and ambiguous-outcome quarantine | Duplicate/conflicting operations and illegal transitions denied |

## Newly corrected weaknesses

1. Policy revision and decision replay state previously lived inside one process.
   It now uses transactional shared state and survives verifier restart.
2. Workload assertions previously identified a certificate but were reusable
   during their validity window. They now carry a unique assertion ID and bind
   to the authenticated sender proof's exact body hash.
3. An initial consistency-floor implementation conflicted with a higher stored
   revision after restart. Floors now use a raise-only atomic operation.
4. Raw request bytes were initially passed through JSON canonicalization for
   channel binding. Regression testing caught this; the already-verified sender
   proof body hash is now used directly.
