# AAK v0.5 architecture and deployment contract

## Enforced flow

1. The model host submits a proposal and holds no downstream credentials.
2. Independently administered authorities evaluate the proposal and sign the
   same immutable claim.
3. The gateway requires a threshold of distinct valid signatures and binds the
   claim to the expected policy hash, system version and downstream audience.
4. The executor presents the quorum bundle and gateway dispatch capability
   using its short-lived workload identity.
5. The downstream resource owner repeats every cryptographic and semantic
   check; the gateway is not trusted merely because it is the gateway.
6. Principal and global budgets plus the nonce are consumed atomically.
7. A signed external `prepared` checkpoint must exist before the effect.
8. The downstream tool performs one narrow operation and records a signed
   completion checkpoint. Missing completion evidence quarantines the workload
   without falsely telling the caller that the effect failed.

## Production trust domains

| Domain | Credential | Must not possess |
|---|---|---|
| Model host | Proposal-only identity | Signing or downstream credentials |
| Policy authority A/B/C | Its own HSM signing key | Gateway or effect credentials |
| Gateway | Dispatch signing key | Downstream effect credential |
| Executor | Short-lived workload identity | Policy signing key |
| Downstream owner | Narrow resource credential | Authority private keys |
| Audit anchor | Audit HSM key and WORM storage | Effect credential |

Use public-key-only verifier objects outside each key-owning domain. Require
mutual TLS, default-deny service policies, read-only signed deployment images,
independent administrators, KMS/HSM keys, globally serializable nonce/budget
storage and an immutable off-account audit replica.

## Precise guarantee

AAK aims to make this invariant true:

> No AI output and no single non-resource-owner component can independently
> create an unauthorized consequential effect.

It cannot stop a fully compromised final resource owner from modifying its own
database or actuator, nor coordinated compromise that reaches the configured
quorum and downstream enforcement boundary. Those are irreducible roots of
trust, not prompt-engineering problems.
