# AAK v1.2.0-rc1 distributed staging report

## Outcome

This release moves the Action Assurance Gateway toward independent runtime
boundaries without claiming production certification. It adds deployable
configuration and fail-closed adapters for OPA, OIDC, PostgreSQL, executor
egress and credential brokering.

## Controls added

- OPA requests use a fixed HTTPS endpoint, bounded timeout and exact response
  schema. Denials, timeouts, unknown fields and invalid effect units fail closed.
- Workload tokens require a pinned Ed25519 key, exact issuer and audience,
  SPIFFE-shaped subject, short lifetime, certificate confirmation and durable
  single-use token identifier. Duplicate JSON claims fail closed.
- PostgreSQL state uses serializable transactions for nonces, idempotency,
  resource versions, monotonic assurance floors and integer budgets. A denied
  transaction raises internally so all provisional writes roll back.
- Executor destinations match an exact HTTPS origin. Credentials are requested
  only after the destination passes the egress check.
- The Compose topology separates authority and identity networks, publishes no
  host ports, mounts secrets from ignored files and runs OPA over TLS.

## Evidence

- 143 deterministic unit and regression tests passed.
- 100,000 synthetic distributed-boundary attacks completed with zero
  unauthorized acceptances and zero crashes.
- Python byte-code compilation completed successfully.
- Docker was not installed in the build environment, so Compose parsing,
  container startup, live OPA/OIDC/PostgreSQL integration, failover, TLS chain
  validation and network-policy enforcement remain unverified here.

development identity settings, pin verified image digests, add an mTLS ingress
