# AAK v1.4.0-rc1 mTLS service-boundary report

## Objective

Close the highest-risk gap between an in-process authority prototype and a
deployable multi-service control plane without claiming evidence that was not
collected. The protected path is resource verifier to audit anchor to effect
broker to provider operation.

## Security changes

- The effect broker independently verifies the signed action envelope, signed
  manifest, exact canonical call, audience, expiry, action hash and approved
  destination before any provider credential can be used.
- Resource, broker and audit contracts have strict request and response schemas.
  Missing, additional, malformed and wrongly typed fields fail closed.
- The HTTP transport requires TLS 1.3 and a client certificate. Each endpoint
  accepts only an exact operator-configured SPIFFE URI SAN.
- JSON request bodies are bounded and reject duplicate keys. Redirects are
  rejected rather than followed across an authority boundary.
- Envelope and manifest verification supports overlapping signing keys,
  activation windows, expiry and timed revocation.
- Staging secret generation creates short-lived, separate workload identities.
  The evidence gate cannot report success for a partial infrastructure run.

## Local evidence collected

- 180 deterministic unit and integration tests passed with resource warnings
  promoted to errors.
- A real loopback TLS 1.3 mutual-TLS service accepted the authorized resource
  certificate and rejected a different certificate signed by the same CA.
- 100,000 malformed and unauthorized remote broker requests produced zero
  provider calls, zero unauthorized acceptances and zero crashes.
- The full pre-existing compound, assurance, gateway, staging, distributed,
  resilience, HTTP and mutual-TLS gates are rerun for the packaged release.

## Evidence not collected in this environment

Docker was unavailable. Therefore this report does not claim live container
isolation, orchestrator network-policy enforcement, live OPA/OIDC/PostgreSQL
interoperability, certificate rotation under traffic, simultaneous process
failure containment or database failover. `deploy/staging/run-evidence-gate.sh`
preserves these as explicit non-bypassable promotion gates.

## Residual trust

AAK cannot contain simultaneous compromise of all independent enforcement
services and their administrators. Host kernels, trusted provider adapters,
HSM/KMS implementations, certificate authorities, database rollback defenses
and operational recovery procedures remain part of the production trusted
computing base and require independent review.
