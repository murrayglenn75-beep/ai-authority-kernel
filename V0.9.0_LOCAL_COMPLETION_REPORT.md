# AAK v0.9.0 local defensive completion report

## Newly tested in this phase

- Dependency advisory audit: no known vulnerabilities in the locked runtime set
- Static analysis: zero Bandit findings across the AAK package
- Secret-pattern inspection: zero matching project files
- Python compilation: passed
- Reproducible build: two wheels built with the same epoch were byte-identical
- CycloneDX 1.6 SBOM: generated and schema-validated
- Clean locked runtime: installed and passed the complete unit suite
- Restart persistence: nonce and transaction replay protection survived restart
- Multi-process database race: one reservation, 199 duplicate denials
- Corrupt database: initialization failed closed
- Simulated storage-write failure: transaction rolled back and did not burn the nonce
- Clock anomalies: boolean, negative and text trusted-time values rejected
- Synthetic prompt/RAG/tool injection: text could not alter registered authority
- Mutual TLS: valid client identity accepted; missing and foreign certificates rejected
- Audit logging failures: explicitly mark audit degradation and stop future authorization

## Defensive improvements made from findings

1. Removed all dynamic SQL table interpolation, even though the original table
   choice was internal and not attacker-controlled.
2. Replaced silent audit exception handling with explicit degraded state and
   fail-closed authorization.
3. Added strict trusted-time validation to the core, transport, gateway,
   downstream and policy boundaries.
4. Added a tested runtime dependency lock for repeatable Git Bash installation.
5. Added database restart, multi-process, corruption and rollback regression tests.
6. Added a real local mTLS identity test using synthetic certificates.

## Still not testable in this local environment

These items are not marked as passed:

- Real cloud KMS/HSM custody, throttling, rotation and administrator separation
- SPIFFE/SPIRE or cloud workload identity across actual hosts
- Kubernetes/container isolation, escape resistance and network policy
- Multi-region partitions, failover, replication and control-plane outage
- Production PostgreSQL clusters, connection pools and failover during commit
- Real payment, PIX, email, storage or infrastructure-provider idempotency
- Provider-side ambiguous external effects and long-running reconciliation
- Internet-scale DDoS, bandwidth saturation and millions of sockets
- Real LLM/provider compromise, live MCP/plugin poisoning and multi-agent collusion
- CI branch protection, hosted runner compromise and deployment admission
- Independent penetration test, cryptographic audit or formal verification
- Human phishing, insider collusion, approval fatigue and recovery exercises
- GDPR, LGPD, EU AI Act or sector-specific legal certification

Testing those categories requires a dedicated deployed staging environment,
provider test accounts, isolated keys, observability and—in several cases—an
independent qualified assessor. Local simulation cannot honestly certify them.
